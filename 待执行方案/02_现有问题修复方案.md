### 1.2 stop() 可靠发送（修 P2）
文件：ptzcontroller.cpp:160-167

```cpp
void PTZController::stop()
{
    // 先作废旧队列，再把 3 个 stop 包排入命令队列（见 1.3），由 m_cmdTimer 按 10ms 节拍发出
    m_cmdQueue.clear();
    m_cmdTimer->stop();
    QByteArray pkt = buildPelcoDPacket(0x00, 0x00, 0x00, 0x00);
    for (int i = 0; i < 3; ++i) m_cmdQueue.enqueue(pkt);
    m_cmdTimer->start();

    m_currentPanSpeed = 0.0f;
    m_currentTiltSpeed = 0.0f;
    m_stopWatchdog->stop();
}
```
> 不要用 `QThread::msleep` 连发：stop() 常被 UI 线程同步调用会卡界面，且 1.3 已引入命令队列，两套发送机制并存会互相干扰。

停止看门狗——**必须用 single-shot 定时器**：
- 新增成员 `QTimer* m_stopWatchdog`，`setSingleShot(true)`，interval 500ms；
- 每次下发 moveTo / moveDirection 后执行 `m_stopWatchdog->start()`（start() 会重置已在运行的单次定时器，语义即"距最后一条命令已过 500ms"）；
- 超时槽：若 m_currentPanSpeed / m_currentTiltSpeed 非零则补发 stop。

> 不要写成"周期 500ms 检查速度非零就补 stop"：手动按住方向键或跟踪闭环持续运动时速度本来就非零，会被误判为失控并周期性插入 stop，造成抖动。

## 二、日志系统（修 C2/C3/P9）

文件：logmanager.h / logmanager.cpp

方案：生产者-消费者异步写盘。
1. `handleMessage` 只做：格式化字符串（轻量）→ `m_logQueue.enqueue(line)`，锁粒度仅为入队；
2. 新增 `QThread m_writerThread` + 写入循环：批量 dequeue（攒 16 行或 100ms）→ 一次 flush；
3. 文件名粒度从分钟改为天：`QString("yyyyMMdd") + ".log"`；
4. 单文件超过 50MB 时滚动为 `yyyyMMdd_1.log`；
5. `startLogging/stopLogging` 增加主线程断言：
   ```cpp
   Q_ASSERT(QThread::currentThread() == qApp->thread());
   ```
6. 写盘线程退出前 flush 队列剩余日志。

改动量：logmanager.h 增加 ~20 行，logmanager.cpp 改 handleMessage 与新增线程函数，预计 150 行以内。
收益：跟踪线程每帧多条 qDebug 不再被磁盘 IO 阻塞。

### 3.4 stopStream 停解码线程（修 C6）
文件：devicemanager.cpp:460-477 末尾追加：
```cpp
if (m_decodeThread && m_decodeThread->isRunning()) {
    m_decodeThread->stop();
    m_decodeThread->wait();
}
```
注意：DecodeThread::stop 后再 start 需要可重入——当前 m_running 是 atomic 且 stop() 置 false；重新 start() 前要复位 m_running=true。**但只复位 m_running 不够**：ThreadSafeQueue::stop() 只把 m_stopped 置 true，而 clear() 并不复位它（ThreadSafeQueue.h:46-54），此后 push() 会直接丢数据（:20）、waitAndPop() 恒返回 false（:41），线程复活后只会空转。需要给队列补一个复位接口：

```cpp
// ThreadSafeQueue.h 新增
void reset() { QMutexLocker locker(&m_mutex); m_queue.clear(); m_stopped = false; }

// DecodeThread
void DecodeThread::restart() { m_dataQueue.reset(); m_running = true; start(); }
```
startStream 中改调 restart()。

### 3.5 startStream 移出 UI 线程（修 C7）

## 四、FFmpeg 管线（修 V1/V2/V3/V5/V6/V7）

### 4.1 decodeFrame 规范化（修 V1）
文件：videodecoder.cpp:93-150
```cpp
m_packet->data = const_cast<uint8_t*>(data);
m_packet->size = size;
m_packet->pts  = AV_NOPTS_VALUE;
int ret = avcodec_send_packet(m_codecContext, m_packet);
if (ret < 0 && ret != AVERROR(EAGAIN)) return QImage();
// send 返回后立即规范清理，避免 m_packet 悬垂指向调用方的 QByteArray
av_packet_unref(m_packet);

// receive 循环：把解码器内部缓存的输出帧全部取尽，只保留最后一帧
bool got = false;
while (true) {
    ret = avcodec_receive_frame(m_codecContext, m_frame);
    if (ret == AVERROR(EAGAIN) || ret == AVERROR_EOF) break;
    if (ret < 0) break;
    got = true;     // 每轮覆盖同一 m_frame，receive 内部会自动 unref 上一帧
}                   //   → 中间帧不触发 sws_scale，这就是"丢帧降载"

if (!got) return QImage();
QImage image = convertAndCopy();   // 仅对最后一帧做 sws_scale + image.copy()
av_frame_unref(m_frame);
return image;
```
> 要点：(1) 不要在 receive 循环里逐帧 convertAndCopy，否则等于没省 CPU；(2) 结束统一 av_packet_unref / av_frame_unref，落实 01 文档 V1 的"规范清理"。

### 4.2 分辨率/格式变化检测（修 V2、V7）
文件：RecordThread.cpp:214-226、videodecoder.cpp:112
```cpp
// 统一的重建条件
if (!m_swsCtx || m_lastInW != frame->width || m_lastInH != frame->height
    || m_lastInFmt != frame->format) {
    if (m_swsCtx) sws_freeContext(m_swsCtx);
```

RecordThread 中分辨率变化时：释放旧 m_yuvBuffer → av_image_alloc 新尺寸 → 重新 fill m_yuvFrame；编码器分辨率若与首帧不同，录像继续用首帧分辨率（sws 缩放），行为不变。
