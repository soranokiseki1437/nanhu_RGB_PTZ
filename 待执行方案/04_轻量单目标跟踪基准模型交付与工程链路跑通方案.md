## 一、 为什么选择 LightTrack 原版作为方案 04 交付基座？

在地面/车载光电云台长焦对空跟踪场景中，摸清 RK3588 边缘端硬件底座需要一个**真正跟得住目标、尺度不发散、硬件算子 100% 直通**的成熟模型：

1. **实测性能真实可靠（真正跟得住）**：
   - LightTrack 原版（`LightTrackM.pth`）在本地 20 组真机长焦 Anti-UAV 航迹（24,919 帧）实测表现稳定：**Success AUC 达到 52.24%**，**跟丢率仅 14.16%（全场最低！）**，DP@20 达到 66.06%；
   - 依赖其在 ImageNet-VID、GOT-10k、COCO、LaSOT 等海量跟踪数据集上充分预训练的先验权重，能够稳定适应远距离小目标机动与长时连续跟踪，彻底杜绝尺度发散与剧烈抖动；
2. **端侧极致轻量与高吞吐**：
   - 模型参数量仅 **1.60M**，计算量仅 **0.58 GFLOPs**；
   - 纯模型 GPU 推理耗时仅 **2.1 ms**（纯算力帧率 $> 450\text{ FPS}$），完全满足云台 60 FPS 硬实时机电伺服闭环；
3. **100% 契合 RK3588 NPU 原生硬件算子**：
   - 全网络拓扑基于神经架构搜索（NAS）得到的深度可分离卷积（DW-Conv）、点卷积（Pointwise Conv）与轻量互相关运算，完全属于 RK3588 脉动阵列黄金算子集，INT8 定点量化零精度骤降，零“Fallback to CPU”风险；
4. **学术叙事逻辑严密自洽**：
   - 方案 04 交付 LightTrack 原版跑通 RK3588 链路；
   - 后续方案 06 以此为绝对基线开展自研结构重参数化（Rep-Backbone）、浅层细节融合（MFFN）与动态注意力匹配头（DAC-Head）的三阶段重训与消融，学术对比水到渠成。

## 二、 LightTrack 静态计算图解耦与 ONNX 导出规范

为杜绝动态维度导致的 NPU 编译失败，将 LightTrack 原版模型解耦为两组纯静态 ONNX 模型：

```
                    ┌────────────────────────────────────────────────────────┐
                    │          LightTrack 原版双分支静态计算图与接口          │
                    └────────────────────────────────────────────────────────┘
                                                 │
             ┌───────────────────────────────────┴───────────────────────────────────┐
             ▼                                                                       ▼
    【模板分支 (Template Branch)】                                          【搜索分支 (Search Branch)】
       静态输入: 1x3x127x127                                                   静态输入: 1x3x255x255
             │                                                                       │
     [LightTrack 官方骨干 (DW-Conv)]                                         [LightTrack 官方骨干 (共享权重)]
             │ 单次前向提取深层特征                                                  │ 逐帧高频前向提取
             │                                                                       │
     输出静态模板特征 z: 1x96x8x8                                            输出静态搜索特征 x: 1x96x16x16
             │ (首帧截取后常驻显存/NPU)                                              │ (高频逐帧抽取)
             └───────────────────────────────────┬───────────────────────────────────┘
                                                 │
                                                 ▼
                             【LightTrack 原版互相关匹配与预测头】
                             • 输入: 模板特征 z (1x96x8x8) + 搜索特征 x (1x96x16x16)
                             • 输出分类响应图: 1x1x16x16 (目标中心置信度)
                             • 输出边界回归图: 1x4x16x16 (边界偏移量 l, t, r, b)
```

### 2.1 静态 ONNX 模型导出清单
1. **模板特征网络 (`models/lighttrack_template.onnx`)**：
   - 输入张量：`template_img: float32[1, 3, 127, 127]`
   - 输出张量：`template_feat: float32[1, 96, 8, 8]`
   - 物理尺寸：约 2.5 MB；目标初始化时单次调用。
2. **搜索与预测网络 (`models/lighttrack_search.onnx`)**：
   - 输入张量 1：`search_img: float32[1, 3, 255, 255]`
   - 输入张量 2：`template_feat: float32[1, 96, 8, 8]`
   - 输出张量 1：`cls_score: float32[1, 1, 16, 16]`
   - 输出张量 2：`reg_dist: float32[1, 4, 16, 16]`
   - 物理尺寸：约 5.5 MB；纯推理耗时 $\le 2.2\text{ ms}$。

## 三、 C++ 侧工程接入与系统闭环集成

### 3.1 C++ 跟踪器封装契约 (`OnnxSotTracker`)
在 C++ 侧基于 ONNX Runtime DirectML 封装轻量跟踪器类，直接兼容 `ObjectTracker`：

```cpp
class OnnxSotTracker {
public:
    OnnxSotTracker();
    ~OnnxSotTracker();

    // 初始化 DirectML 执行提供者，加载模板与搜索 ONNX
    bool init(const std::string& templateOnnx, const std::string& searchOnnx);

    // 接收目标框，提取并缓存首帧模板特征
    bool initTemplate(const cv::Mat& frame, const cv::Rect2d& initBbox);

    // 逐帧连续跟踪，输出当前帧目标预测位置与置信度
    bool track(const cv::Mat& frame, cv::Rect2d& outBbox, float& outConfidence);

private:
    // 恒定上下文边缘填充（Context padding）与双线性切片
    cv::Mat getSubwindow(const cv::Mat& img, cv::Point2f center, int modelSz, int originalSz);

    // 预测网格解码与尺寸平滑滤波
    cv::Rect2d decodeBbox(const float* regData, const float* clsData, cv::Point2f center, float scale);
};
```

### 3.2 与 AMFT 状态机及云台控制协同
1. **首帧截取与跟踪锁定**：操作员框选或方案 03 的 YOLO 检测器触发重定位后，调用 `initTemplate` 锁定目标；
2. **高频闭环驱动**：每帧以 60 FPS 频率调用 `track`，输出脱靶量 $(e_x, e_y)$ 并传递至 `TrackingController` 计算 PID 角速度指令，驱动 Pelco-D 云台伺服；
3. **失锁判断与检测唤醒**：跟踪置信度跌破阈值（$\tau_t = 0.45$）时，通知 `AMFTEvaluator` 判定跟踪退化，按需唤醒 YOLO 异步重检。
