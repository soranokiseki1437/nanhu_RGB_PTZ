## 一、 方案定位与工程交付目标

在地面/车载光电云台对空防御系统中，整个感知运控系统的工程主干遵循“Tracer Bullet”极简贯通策略：
1. **方案 03 已完成**：已交付 5 款微调级 YOLO 检测 ONNX 模型（YOLO11n/s、YOLOv8n/s），实现全局目标捕获；
2. **方案 04（本方案）**：交付自研轻量级单目标跟踪（SOT）基准模型，完成纯静态双分支 ONNX 导出与 C++ 链路打通；
3. **方案 05（接力推进）**：将方案 03 与方案 04 交付的检测与跟踪模型直接部署至 RK3588 NPU，摸清嵌入式端算子直通率、INT8 量化损耗、多核调度与整机伺服闭环延迟；
4. **方案 06 及后续方案**：在 RK3588 底层硬件链路完全走通后，再集中展开大规模数据重训、损失函数消融对比与硕士学位论文核心创新攻坚。

## 二、 基准跟踪网络架构与静态计算图定义

基准模型采用轻量孪生架构，由共享权重的结构重参数化骨干（Rep-Backbone）、多尺度特征融合模块（MFFN）与动态注意力匹配头（DAC-Head）构成：

```
                    ┌────────────────────────────────────────────────────────┐
                    │            基准轻量 SOT 模型拓扑与静态计算图            │
                    └────────────────────────────────────────────────────────┘
                                                 │
             ┌───────────────────────────────────┴───────────────────────────────────┐
             ▼                                                                       ▼
    【模板分支 (Template Branch)】                                          【搜索分支 (Search Branch)】
       静态输入: 1x3x127x127                                                   静态输入: 1x3x255x255
             │                                                                       │
     [Rep-Backbone (推理态单路Conv3x3)]                                      [Rep-Backbone (共享权重)]
             │ 提取浅层 P2 与深层 P4                                                 │ 提取浅层 P2 与深层 P4
             │                                                                       │
     [MFFN 多尺度特征融合模块]                                               [MFFN 多尺度特征融合模块]
             │                                                                       │
     输出静态模板特征 z: 1x96x8x8                                            输出静态搜索特征 x: 1x96x16x16
             │ (首帧抽取后常驻显存/内存)                                             │ (高频逐帧抽取)
             └───────────────────────────────────┬───────────────────────────────────┘
                                                 │
                                                 ▼
                             【DAC-Head 动态相关匹配与预测头】
                             • 输入: 模板特征 z (1x96x8x8) + 搜索特征 x (1x96x16x16)
                             • 输出分类响应图: 1x1x16x16 (目标中心置信度)
                             • 输出尺度回归图: 1x4x16x16 (边界偏移量 l, t, r, b)
```

### 2.1 纯静态 ONNX 模型规范（100% 契合 DirectML 与 RKNN 硬件要求）
为杜绝动态尺寸导致的 NPU 编译失败或回退 CPU，模型解耦为两组纯静态计算图导出：
1. **模板提取网络 (`models/sot_template.onnx`)**：
   - 输入张量：`template: float32[1, 3, 127, 127]`
   - 输出张量：`zf: float32[1, 96, 8, 8]`
   - 执行特性：单次目标初始化时调用 1 次，输出特征常驻显存或 NPU 缓存。
2. **搜索与匹配网络 (`models/sot_search.onnx`)**：
   - 输入张量 1：`search: float32[1, 3, 255, 255]`
   - 输入张量 2：`zf: float32[1, 96, 8, 8]`
   - 输出张量 1：`cls_score: float32[1, 1, 16, 16]`
   - 输出张量 2：`bbox_reg: float32[1, 4, 16, 16]`
   - 执行特性：每帧视频输入高频调用，纯网络推理时延 $\le 2.5\text{ ms}$。

## 三、 C++ 引擎接入与系统闭环集成

### 3.1 C++ 跟踪器封装契约 (`OnnxSotTracker`)
在工程代码中构建标准化跟踪接口，完全兼容既有 `IDetector` 与 `ObjectTracker` 体系：

```cpp
class OnnxSotTracker {
public:
    OnnxSotTracker();
    ~OnnxSotTracker();

    // 加载静态 ONNX 权重并初始化 DirectML 执行提供者
    bool init(const std::string& templateModelPath, const std::string& searchModelPath);

    // 接收目标初始框，提取初始模板特征 zf
    bool initTemplate(const cv::Mat& frame, const cv::Rect2d& initBbox);

    // 逐帧连续跟踪，输出当前帧目标预测位置与置信度
    bool track(const cv::Mat& frame, cv::Rect2d& outBbox, float& outConfidence);

private:
    // 图像裁剪预处理（保持与训练一致的 Context 平铺与双线性插值）
    cv::Mat getSubwindow(const cv::Mat& img, cv::Point2f center, int modelSz, int originalSz);

    // 解码预测网格输出，映射回全图绝对坐标
    cv::Rect2d decodeBbox(const float* regData, const float* clsData, cv::Point2f center, float scale);
};
```

### 3.2 与 AMFT 状态机及云台控制协同
1. **首帧截取与跟踪锁定**：用户手动框选或方案 03 的 YOLO 检测器触发重定位后，调用 `initTemplate` 锁定目标；
2. **高频闭环驱动**：每帧以 60 FPS 频率调用 `track`，输出脱靶量 $(e_x, e_y)$ 并传递至 `TrackingController` 计算 PID 角速度指令，驱动 Pelco-D 云台伺服；
3. **失锁判断与检测唤醒**：跟踪置信度跌破阈值（$\tau_t = 0.45$）时，通知 `AMFTEvaluator` 判定跟踪退化，按需唤醒 YOLO 异步重检。
