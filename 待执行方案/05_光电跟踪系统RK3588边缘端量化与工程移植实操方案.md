## 一、 硬件特性与算子原生兼容基准 (RK3588 三核 NPU)

RK3588 配备 3 个独立的 NPU 核心，标称综合算力 6.0 TOPS。硬件架构基于专有脉动阵列，模型转换时必须严格遵循算子直通规范：

```
                    ┌──────────────────────────────────────────────┐
                    │          RK3588 三核 NPU 算子执行特性         │
                    └──────────────────────────────────────────────┘
                                           │
         ┌─────────────────────────────────┴─────────────────────────────────┐
         ▼                                                                   ▼
【NPU 硬件原生高吞吐算子（100% 满载直通）】                 【高危算子（会导致量化失败或回退 CPU）】
• 标准 2D 卷积 (Conv2d) 与 深度可分离卷积 (DW-Conv)          • 动态尺寸变换 (Dynamic Shape / Dynamic Reshape)
• 1x1 点卷积 (Pointwise Conv) 与 结构重参数化融合成单路      • 复杂跨注意力矩阵相乘 (Multi-Head Cross-Attention)
• 常用池化 (MaxPool2d / AvgPool2d)                          • 非标准非线性激活 (复杂 GELU、Swish 大核查表)
• 常用硬件激活 (ReLU, ReLU6, Hardswish, SiLU)              • 稀疏采样与可变形卷积 (Deformable Conv)
• 特征通道拼接与残差加法 (Concat, Add)                      • 频繁的数据维度置换 (Frequent Transpose / Permute)
```

### 1.1 算子兼容性硬约束
- **静态尺寸契约**：所有输入必须全静态固定（YOLO 为 $1\times 3\times 640\times 640$，SOT 模板为 $1\times 3\times 127\times 127$，SOT 搜索区为 $1\times 3\times 255\times 255$）；
- **后处理剥离契约**：模型内部严禁打包 NMS 等动态循环算子，NMS 与后处理 100% 保持纯 C++ 执行。

## 二、 全系统多模型 INT8 量化转换规范

通过 Linux 宿主机安装的 `rknn-toolkit2`（v2.x）统一执行量化转换：

### 2.1 检测模型量化脚本 (`scripts/convert_yolo_rknn.py`)
```python
from rknn.api import RKNN

def convert_yolo(onnx_path, rknn_out, calib_dataset):
    rknn = RKNN(verbose=False)
    
    # 针对 RK3588 配置目标平台与量化均值方差
    rknn.config(
        mean_values=[[0, 0, 0]],
        std_values=[[255, 255, 255]],
        target_platform="rk3588"
    )
    
    # 载入纯净静态 ONNX
    ret = rknn.load_onnx(model=onnx_path)
    assert ret == 0, "加载 ONNX 失败！"
    
    # 构建 INT8 量化模型（使用非对称非饱和量化算法）
    ret = rknn.build(
        do_quantization=True,
        dataset=calib_dataset
    )
    assert ret == 0, "模型量化构建失败！"
    
    # 导出 RKNN 文件
    rknn.export_rknn(rknn_out)
    print(f"成功导出: {rknn_out}")
    rknn.release()

if __name__ == "__main__":
    convert_yolo("models/yolo11s.onnx", "models/yolo11s.rknn", "data/calib_detection.txt")
```

### 2.2 单目标跟踪模型量化脚本 (`scripts/convert_sot_rknn.py`)
针对 [方案 04](file:///d:/PyProjects/RGB_PTZ_Integrated/待执行方案/04_基于轻量深度网络的可见光云台单目标跟踪实操方案.md) 的 LightTrack 架构，将解耦后的模板与搜索分支分别转换：
```python
from rknn.api import RKNN

    rknn.build(do_quantization=True, dataset=calib_txt)

    convert_sot_branch("models/sot_search.onnx", "models/sot_search.rknn", "data/calib_sot_x.txt")
```

## 三、 嵌入式 C++ 部署拓扑与多核 NPU 调度

在 aarch64 Linux 上，业务代码继承现有面向对象抽象，底层驱动无缝切换为 `librknnrt.so`：

```
                    ┌────────────────────────────────────────────────────────┐
                    │          可见光视频采集 / RTSP 解码流 (30/60 FPS)       │
                    └────────────────────────────────────────────────────────┘
                                                │
                                                ▼
                    ┌────────────────────────────────────────────────────────┐
                    │      AMFT 协同状态机 (纯 C++17，完全复用方案 02 逻辑)     │
                    └────────────────────────────────────────────────────────┘
                                                │
                     ┌──────────────────────────┴──────────────────────────┐
                     ▼ (常态: 98% 帧率)                                     ▼ (异常: 2% 帧率唤醒)
       ┌───────────────────────────────┐                     ┌───────────────────────────────┐
       │   RknnSotTracker (方案 04)    │                     │ RknnDetector + VaL_CNN (方案03)│
       │    绑定 NPU Core 0 (单核)     │                     │     绑定 NPU Core 1+2 (双核)  │
       │  • 耗时: 2.5 ~ 4.0 ms          │                     │  • YOLO初筛 + VaL_CNN二级校验 │
       │  • 满帧 60 FPS 极速运行        │                     │  • 目标找回后下一帧强制休眠   │
       └───────────────┬───────────────┘                     └───────────────┬───────────────┘
                       │                                                     │
                       └──────────────────────────┬──────────────────────────┘
                                                  ▼ 输出统一 TrackResult
                               ┌─────────────────────────────────────┐
                               │   TrackingController 伺服闭环       │
                               │  (速度前馈 + PID 计算，耗时 < 0.1ms) │
                               └──────────────────┬──────────────────┘
                                                  ▼
                               ┌─────────────────────────────────────┐
                               │   Pelco-D 串口驱动下发云台电机指令   │
                               └─────────────────────────────────────┘
```

### 3.1 NPU 核心亲和性调度（Core Mask）
调用 `rknn_set_core_mask()` 实现算力隔离：
- **SOT 跟踪器**：设置 `RKNN_NPU_CORE_0`，独占核心 0，保证高频低时延伺服不受外部抢占；
- **YOLO 检测器**：设置 `RKNN_NPU_CORE_1_2`，在按需触发时并发利用核心 1 和核心 2，大幅压低全局全图扫描时延。

### 3.2 零拷贝缓冲区管理
嵌入式端直接通过 DRM (Direct Rendering Manager) / RGA 分配连续物理内存（DMA-BUF），将解码帧通过物理地址直传给 NPU 输入缓存，彻底消除 CPU 内存拷贝开销。
