## 一、 为什么在可见光云台场景中引入轻量深度 SOT？

在长焦可见光反无人机与空地目标跟踪任务中，跟踪内核的辨识力与鲁棒性直接决定云台闭环跟踪的持续时间：

| 评估维度 | 传统相关滤波 (DSST) | 本方案轻量深度 SOT (LightTrack/RepSOT) | 解决的核心痛点 |
| :--- | :---: | :---: | :--- |
| **色彩空间利用** | 强制转换灰度，色彩辨识度完全丢失 | 原生利用 3 通道深浅层 RGB 色彩卷积特征 | 空域复杂云层、地面树丛/建筑同灰度杂波背景下的抗干扰能力显著提升 |
| **外观形变鲁棒性** | 弱（依靠手工 HOG 浅层特征，模板极易受污染） | 强（高维卷积提取结构几何特征，模板常驻） | 目标大角度俯仰、快速翻滚或部分阴影遮挡时保持稳定锁定 |
| **尺度自适应** | 粗粒度多尺度池（计算量倍增，变倍时易抖动） | 卷积回归头端到端预测连续尺度变化率 $(w_t, h_t)$ | 长焦镜头持续光学变焦时光轴平滑，无边框高频抽搐 |
| **DirectML 推理时延** | 纯 CPU 计算（单帧约 1.5~2ms） | GPU 硬件加速单帧纯推理 **$2.5\sim 4.0\text{ ms}$** | 稳定维持 60 FPS 满帧伺服刷新率，脱靶量输出超平滑 |

## 二、 轻量 SOT 候选网络选型与架构设计

面向实时光电伺服闭环的高帧率与低时延要求，聚焦于两大代表性轻量卷积 SOT 架构：

```
                    ┌──────────────────────────────────────────────┐
                    │          可见光单目标深度跟踪候选架构对比          │
                    └──────────────────────────────────────────────┘
                                           │
         ┌─────────────────────────────────┴─────────────────────────────────┐
         ▼                                                                   ▼
【LightTrack (ICCV Oral / TPAMI)】                          【RepSOT (CVPR 结构重参数化)】
• 参数量: 1.6 M / 算力: 0.6 GFLOPs                          • 参数量: 2.1 M / 算力: 0.8 GFLOPs
• 神经架构搜索 (NAS) + 深度可分离卷积 (DW-Conv)             • 训练态多分支多尺度特征提取，推理态静态融合为单路 Conv
• 优势: 双分支计算完全静态，DirectML 显存访存开销极低         • 优势: 纯 3x3 卷积拓扑，硬件并行度与吞吐极限最高
• 定位: 首选基准（稳定高帧率、跨后端一致性极强）             • 定位: 进阶选型（极致利用显存带宽）
```

### 2.1 双阶段模型解耦与模板驻留机制
为了将单帧跟踪延时压至极限，网络严格采用模板与搜索区域解耦设计：
1. **模板分支（Template Branch，单次执行）**：
   - 目标初次框选锁定（或重捕成功）时执行 1 次；
   - 输入尺寸：$1 \times 3 \times 127 \times 127$（RGB 彩色图像）；
   - 输出特征图 $f(z)$ 常驻于 DirectML / GPU 会话显存中，后续跟踪帧直接复用，避免每帧重复计算；
2. **搜索分支（Search Branch，每帧高频执行 30~60 FPS）**：
   - 输入尺寸：$1 \times 3 \times 255 \times 255$（以目标上一帧预测中心裁剪的局部搜索区）；
   - 提取搜索区特征 $f(x)$ 并与常驻模板 $f(z)$ 进行逐通道深度相关（Depthwise Correlation）；
   - 输出固定维度的分类响应图（Classification Map，中心置信度）与边框回归图（Bounding Box Regression Map，中心微调偏移与长宽尺度）。

## 三、 系统集成与 C++ 运行时封装

### 3.1 面向对象接口设计：`ISotTracker`
工程遵循统一抽象模式，在算法层定义与目标检测器 `IDetector` 并列的 SOT 纯虚基类：

```cpp
// 位于 sottracker.h
struct SotResult {
    QRectF targetBox;       // 预测目标外接矩形
    float confidence = 0.0f;// 响应置信度 [0.0, 1.0]
    float psr = 0.0f;       // 类似相关滤波的峰值旁瓣比
    bool isValid = false;   // 本帧预测是否有效
};

class ISotTracker {
public:
    virtual ~ISotTracker() = default;
    
    // 初始化/重置模板（用户框选或检测重捕唤醒）
    virtual bool init(const cv::Mat& rgbFrame, const QRectF& initialBox) = 0;
    
    // 每帧高频跟踪更新
    virtual SotResult track(const cv::Mat& rgbFrame) = 0;
    
    // 释放资源
    virtual void release() = 0;
};
```

### 3.2 DirectML 推理实现：`OnnxSotTracker`
基于微软官方 ONNX Runtime C-API 与 DirectML 构建实现类：
- **前处理优化**：以当前目标中心为基准自适应裁剪 $255\times 255\times 3$ 局部区域，前处理采用纯 C++ / OpenCV `resize` 与减均值除方差，耗时控制在 $< 0.8\text{ ms}$；
- **会话持久化**：保持 DirectML 推理会话常驻，避免每帧重复创建张量开销；
- **输出桥接**：将 `SotResult` 封装为工程既有的统一 `TrackResult`，无缝送入 [TrackingController.cpp](file:///d:/PyProjects/RGB_PTZ_Integrated/trackingcontroller.cpp) 参与速度前馈与误差 PID 运算。

### 3.3 与 AMFT 协同状态机的深度融合
直接复用 [方案 02](file:///d:/PyProjects/RGB_PTZ_Integrated/待执行方案/02_基于自适应多特征融合(AMFT)的光电云台检测-跟踪协同实操方案.md) 已验证闭环的四态流转机：
1. **$S_{\text{conf}}$ 映射**：将 LightTrack 分类响应图的最大峰值及其与次峰比值直接映射为跟踪置信度得分；
2. **$S_{\text{mot}}$ 与 $S_{\text{bg}}$**：保持 [AMFTEvaluator.cpp](file:///d:/PyProjects/RGB_PTZ_Integrated/amftevaluator.cpp) 既有的位置连续性与外围环形背景直方图可区分度评估；
3. **协同重捕闭环**：当动态可靠度 $R_t < \tau_t$ 判定失锁时，保持深度 SOT 模板锁定状态，单次唤醒 [OnnxDetector](file:///d:/PyProjects/RGB_PTZ_Integrated/onnxdetector.cpp) 全图重捕；重捕成功后调用 `ISotTracker::init()` 一键刷新模板特征。
