### 1.4 stopStream 停解码线程（修 C6）
文件：devicemanager.cpp:460-477 末尾追加：
```cpp
if (m_decodeThread && m_decodeThread->isRunning()) {
    m_decodeThread->stop();
    m_decodeThread->wait();
}
```
注意：**只复位 m_running 不够**：ThreadSafeQueue::stop() 只把 m_stopped 置 true，而 clear() 并不复位它，此后 push() 会直接丢数据、waitAndPop() 恒返回 false，线程复活后只会空转。需要给队列补一个复位接口：
```cpp
// ThreadSafeQueue.h 新增
void reset() { QMutexLocker locker(&m_mutex); m_queue.clear(); m_stopped = false; }

// DecodeThread
void DecodeThread::restart() { m_dataQueue.reset(); m_running = true; start(); }
```
startStream 中改调 restart()。

### 1.5 startStream 移出 UI 线程（修 C7）

**验证**：反复 start/stop 预览×100：解码线程能正常复活、无空转丢帧。

## 二、跟踪与 UI（修 C8/C9）

### 2.1 跟踪框绘制去重（修 C8）
文件：mainwindow.cpp:428-474、1096-1106
- `displayImage` 缓存 `m_scaledPixmap` 与对应 `m_frameSize`；
- `onTrackBoxDraw` 不再全量重算，直接用缓存 pixmap + 画框（QPixmap::copy 级开销）。
```cpp
// onTrackBoxDraw:
if (!m_lastFrame.isNull() && !m_scaledPixmap.isNull()) {
    QPixmap pm = m_scaledPixmap;          // 写时复制，绘制时会 detach
    QPainter p(&pm); /* 画框逻辑同 displayImage */ ui->rgbLabelImage->setPixmap(pm);
}
```
（displayImage 每帧更新 m_scaledPixmap 后仍 setPixmap 一次即可。）

> 注意：QPixmap 是写时复制，"浅拷贝 + QPainter"在开始绘制时会 detach，等于每帧仍有一次整幅像素拷贝（只是省掉了 fromImage+scaled 的开销）。若实测 UI 线程 CPU 仍高，改成 QLabel 子类 paintEvent 叠加画框（或独立 overlay 控件 + update(rect) 局部刷新）才是真正的零拷贝方案。

### 2.2 setTarget 异步化（修 C9）
