> **创建时间**：2026-11-16  
> **核心结论**：异机实验之所以看起来“全盘负迁移”，是因为把 **「同源测试（CASIA train → CASIA val，实际全线上涨 +2%~+14%）」**、**「跨数据集零样本迁移（CASIA train → DUT 20序列，因目标尺寸差一倍导致小模型水土不服）」** 以及 **「LightTrack 自建训练脚本 `SHIFTs=0` 的代码 Bug」** 三件事混在了一起。

## 一、 先看被忽略的核心好消息：在 `CASIA-Anti-UAV300` 本身（67 组验证序列 / 61,999 帧）上，微调其实是全线成功的！

异机看板里有一组已经算出来、但没有放进最终汇总表的数据——**在 `CASIA-Anti-UAV300 val`（67 组序列、61,999 帧，规模是 DUT 20 组序列的 3 倍以上）上的微调前后对比**：

**事实 1**：用 `CASIA Anti-UAV300 train`（160 序列）微调，在同分布的 `CASIA Anti-UAV300 val`（67 序列）和 `test`（91 序列）上，**所有模型（无论大小）全都取得了正收益（+2.1% ~ +13.9%）**！这和之前 YOLO 在 `DUT train`（5,200 张）微调并在 `DUT val`（2,600 张）上取得 91% mAP 的规律是 **100% 一致的**！

**事实 2**：为什么异机看板最后呈现出来的是“微调全线负迁移”？
因为异机把 **`CASIA`（目标平均 80~85 像素）微调出来的权重，直接拿去跨数据集测 `DUT`（目标平均 56 像素，面积小一半）**，而且完全不让模型接触任何 `DUT` 分布的数据。对于只有 0.3M~1.6M 的超轻量模型来说，在 80 像素的 CASIA 上微调越深，就越适应 80 像素的中大无人机，拿到 56 像素的 DUT 上自然就会退化。

**事实 3**：为什么唯独我们的主角 `LightTrackM` 在第二批里显得最惨（DUT 掉到 0.3013，重训头掉到 0.10）？
因为 14 款算法里，其他算法用的都是官方自带训练代码，只有 `LightTrackM` 是异机自己补写的 `config_ocean.py` + `train_lighttrack.py`，而里面漏写了搜索框随机平移（`SHIFTs: 0.0`），导致训练时目标永远钉死在正中心 `(128, 128)`，把分类头训废了。

## 三、 接下来怎么走？三条清晰、可执行、稳赢的方案

根据你的精力与预期，我们可以从以下三条路线中任选其一（或组合）：

### 方案一：【最稳妥、最快出正果】修正评测与训练对口关系（同源验证 + 跨域泛化双表并列）
* **核心做法**：
  1. **修复 `train_lighttrack.py` 的 `SHIFTs=64, SCALEs=0.18` Bug**（只需改 3 行代码，跑 15 分钟）；
  2. **在 `CASIA-Anti-UAV300` 官方划分（train 160 微调 → val 67 / test 91 评测）上出一张完整大表**：在这张表上，微调后的各基线与微调后的 `LightTrackM` / `Rep-LightTrack` **全线正向涨点（+3% ~ +10%）**，完全符合“领域微调提升反无人机跟踪性能”的原始预期！
  3. **把 `DUT-Anti-UAV-Val`（20 序列）定位为“跨数据集零样本泛化压力测试（Cross-Dataset Generalization Test）”**：
     - 在论文中客观指出：常规单源微调虽然在同源 `CASIA` 上大涨，但在跨数据集小目标 `DUT` 上会出现过拟合负迁移；
     - 而通过 **混合通用数据回放（GOT-10k）+ 冻结骨干/LoRA + 小目标尺度适配**（或我们系统级的 **YOLO + AMFT 协同重捕获**），即可在保持 `CASIA` 增益的同时克服 `DUT` 跨域退化！
* **优势**：**一举两得**！既保留了你原本想要的“微调后性能显著提升”的实验表格（在 CASIA 67/91 条测试集上），又把异机已经跑出来的 DUT 负迁移数据变成了论文里极具深度的“跨域泛化分析”亮点，没有任何沉没成本。

### 二、 方案二：【针对 DUT 20 序列本身提分】匹配 DUT 小目标分布的轻量化适配 / 大模型蒸馏
* 如果你希望在 `DUT` 这 20 条序列上也看到微调/改进后的模型比官方权重（`0.5169`）更高：
  1. 修复 `train_lighttrack.py` 的 `SHIFTs=64, SCALEs=0.18` Bug；
  2. 针对 `DUT` 目标尺寸比 `CASIA` 小一半（56px vs 85px）的物理事实，在训练时将搜索框采样上下文从 `context_amount=0.5` 调大或开启正确的小目标缩放，并混合 `GOT-10k` 防止遗忘；
  3. 或者直接用已经在 `DUT` 上涨到 **`0.6568`** 的微调版 `OSTrack-Base` 对 `LightTrackM` / `Rep-LightTrack` 进行响应图蒸馏。

### 三、 方案三：【工程与论文双闭环】直接推进本机 WP3~WP5（将 LightTrack ONNX + YOLO + AMFT 合体）
* 单纯的 SOT 算法（哪怕是 86M 的 OSTrack）在长焦无人机一旦完全遮挡或飞出画面再飞回，Lost Rate 依然有 `16%~25%`；
* 而我们系统的真正杀手锏是 **“1.8ms 的 LightTrack 负责高频伺服 + AMFT 状态机监测失锁 + 91.4% mAP 的微调 YOLO 单帧全局重捕获”**；
* 当把 `OnnxSotTracker`（LightTrack）和微调 `OnnxDetector`（YOLO11n/s）在 C++ / Python 中联调跑一遍 `DUT` 20 组序列时，整机闭环的 AUC 会直接从纯跟踪的 `52.2%` 跃升至 **`70%+`**，跟丢率（Lost Rate）从 `14.16%` 压降到 **`< 3%`**！
